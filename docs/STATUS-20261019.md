# G81 / LineageOS 17.1 — daily-use snapshot, 2026-10-19

This is a source/input freeze of the Android 10 installation used daily by its
tester, not a claim that every feature or clean installation has been tested.
The phone was neither flashed nor rebooted during this audit.

## Runtime evidence
- Boot uptime: **12.38 days**; Android boot completed; SELinux **Enforcing**.
- Retained native tombstones are dated October 7 or earlier (latest 11:53),
  before the working snapshot's last boot. Retained ANR files are also October 7
  or earlier. No newer native tombstone/ANR file was found.
- Fatal/ANR markers in retained logcat: **0**;
  new fatal/ANR markers during a passive 60-second observation: **0**.
  Observer exit 124 is the expected timeout, not a device crash.
- Wi-Fi snapshot: enabled/connected. Battery Health HAL reports kernel-backed
  voltage and temperature. The temporary theme-test APK is absent.
- Available DropBox records: {'system_server_strictmode': 34}. These are retained records,
  not proof that no other event has ever occurred. Raw logs remain local.

## Remaining observations
- Mali `__egl_platform_cancel_buffers` still appears (15
  occurrences in the retained log buffer); no associated new fatal crash was
  observed in this audit. The underlying binary warning is not marked fixed.
- Kernel audit retains a camera `/proc/m4u` ioctl denial and app
  `debugfs_ion/clients` search denials. Broad application/debugfs access is not
  added to make logs quiet. Media and hotspot stress tests were not repeated.
- StrictMode disk-access diagnostics remain. Frame timing and memory figures
  are cumulative/snapshots, not controlled performance benchmarks.
- Bluetooth NPE / SystemUI animation-lifetime findings from earlier development
  remain historical issues, not newly reproduced failures in this capture.
- Full clean ROM build and clean-flash validation of the published repository
  layout have not yet been performed. The applied runtime and source/input
  export are separately identified; publication is not a new flashable ROM.

## Other retained non-fatal diagnostics
- `WifiNative` reports a null interface lookup (also seen during passive
  observation); Wi-Fi is connected in the service snapshot. The lookup warning
  is not claimed fixed, and this audit does not prove its cause.
- Bluetooth controller energy reporting is unavailable to BatteryStats; MTK
  RIL logs messages at error priority even for responses/cache decisions.
  Error priority alone is not evidence of a radio crash.
- The framework attempts a fingerprint HAL connection on a board without a
  usable fingerprint sensor; no fingerprint feature is advertised as working.
- Vold reports a legacy `resize` flag and an unavailable F2FS GC statistics
  path; no new storage I/O failure is inferred from those messages.
- Two retained WindowManager screen-freeze records were approximately 0.50 s
  and 1.35 s. They are short UI stalls, not an ANR or proof of a stutter-free
  interface. The passive observation did not reproduce a new fatal failure.
- Sensor HAL `batch`/`flush` messages use error priority, but those lines alone
  do not establish failed sensor delivery. Rotation/motion was not re-tested.
